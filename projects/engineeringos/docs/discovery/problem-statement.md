# Planteamiento del problema

**Proyecto:** EngineeringOS
**Fase:** Discovery inicial
**Día de trabajo:** W01D01
**Issue relacionada:** [#1](https://github.com/JuanCarlosBP/portfolio/issues/1)
**Estado:** Validado en W01D01

## Resumen

EngineeringOS nace para convertir el desarrollo del portfolio en un proceso público, ordenado y verificable. El sistema reunirá planificación, decisiones técnicas, implementación, controles de calidad y evidencias de entrega en un flujo reproducible.

## Situación actual

Sin un sistema común, la información de un proyecto puede quedar distribuida entre notas, tareas, commits, documentos y comprobaciones independientes. Esto dificulta reconstruir qué problema se pretendía resolver, qué decisiones se tomaron, cómo se validó el resultado y si el incremento quedó realmente terminado.

## Problema principal

No existe todavía una estructura única que conecte de forma trazable:

1. La necesidad o problema de partida.
2. El trabajo planificado.
3. Las decisiones técnicas adoptadas.
4. Los cambios realizados.
5. Las pruebas y controles ejecutados.
6. La evidencia de entrega.

## Consecuencias

- Pérdida de contexto entre sesiones de trabajo.
- Dificultad para priorizar tareas y limitar el alcance.
- Decisiones técnicas sin justificación persistente.
- Validaciones que pueden quedar sin registrar.
- Menor capacidad para demostrar el proceso seguido.
- Riesgo de considerar terminado un trabajo sin evidencias suficientes.

## Oportunidad

Un flujo ligero y automatizable puede mejorar la disciplina de entrega y, al mismo tiempo, aportar evidencias públicas para que revisores técnicos y reclutadores evalúen no solo el resultado final, sino también el método de trabajo.

## Hipótesis inicial

Si cada incremento conecta problema, issue, rama, cambios, validaciones y entrega, será más sencillo mantener el contexto, detectar trabajo incompleto y demostrar de forma verificable cómo se construye el software.

## Evidencia disponible

En esta fase la evidencia es exploratoria. La necesidad parte de organizar y hacer reproducible el trabajo del portfolio. La hipótesis deberá validarse mediante el uso real de EngineeringOS durante los siguientes incrementos.

## Pregunta de discovery

¿Cómo podemos crear un sistema suficientemente ligero para utilizarlo cada día, pero suficientemente riguroso para conservar trazabilidad y evidencias verificables?
